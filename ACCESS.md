# Repository access

Keep this repository private. GitHub repository access and HubSpot portal access are separate; neither grants the other.

| Recipient | Suggested repository role | Purpose |
| --- | --- | --- |
| Customer | Read | Clone, install, and receive updates |
| Contractor developing the tool | Write | Push branches and propose pull requests |
| Internal maintainer | Maintain or Admin as needed | Manage releases and repository settings |

An organization owner or repository administrator can invite a specific GitHub username under **Settings → Collaborators and teams → Add people**. Prefer named accounts and repository-scoped access. Remove access when an engagement ends. Recipients can retain downloaded copies after revocation; access removal does not recall those copies.

All collaborators can read the repository's tracked files and history. Keep client configs, CRM exports, record IDs, journals, exception reports, credentials, and browser profiles outside this repository. Share client-specific reports through the client's approved channel.

No customer or contractor invitations are part of the initial repository publication. Add recipients only after the owner identifies them and the intended role.
